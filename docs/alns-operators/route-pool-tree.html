How to read the procedure

1 / Branch and backtrack

Start with no assigned taxis. Choose a complete stored route for the next taxi, mark its requests occupied, and descend. On return, unmark those requests. An unused taxi is an explicit branch, tried last.

The starting incumbent shown here is the result of the same pair/triple warm-start sequence applied to each example pool.

2 / Order and request prices

Request frequency counts taxis whose pools contain it. A taxi’s score sums frequency − 1 over every request in every alternative. Highest score goes first; ties follow taxi ID.

Adjusted profit = route profit − its request prices. Prices are computed before the tree using up to 192 projected-subgradient updates and remain fixed during replay.

3 / Two optimistic bounds

Simple: selected profit + independently best compatible profit for each remaining taxi. It may count mutually conflicting future routes.

Priced: selected profit + all unoccupied request prices + independently best compatible adjusted profits (at least zero). Each request price can be charged only once in a feasible fleet.

Simple bound prunes at U₁ ≤ L + 10⁻⁹. Priced bound prunes at U₂ < L − 10⁻⁷. A leaf updates the incumbent only on a strict improvement.
